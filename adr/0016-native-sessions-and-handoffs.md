# 切换 Agent 时保留原生会话，交接按规则挑选原文

同一个会话里换 Agent、换实例或重启应用以后，上下文以前丢得很多：切换时会话里所有原生会话都被停掉，交接只有最近三条消息和三个工具名，重启后则悄悄换成一个空的原生会话。参照 t3code 的 `orchestration-v2`，现在的做法是：原生会话能接上就接上，接不上的部分用交接补，交接里是按规则挑出来的原文。

- **原生会话**：切走时只关子进程，会话行标成停放（`parked`），原生会话本身留着；Host 重启后遗留的（`orphaned`）也一样。下一次用到这个实例时直接 resume；同一个 Agent 的另一个实例，只要配置目录相同（Claude 的 `CLAUDE_CONFIG_DIR`、Codex 的 `CODEX_HOME`，由 driver 的 `continuationKey` 给出），就 fork 一份过来。原生会话已经不存在时（CLI 报找不到），这一轮改开新会话，并带上之前的整段交接，不让 run 失败。
- **交接**：只补原生会话没见过的部分。接回原来的原生会话时，只交接它离开之后发生的事；开新会话时才交接整个会话；接回后中间什么也没发生，就不交接。内容从会话条目里挑：用户消息、回答、命令（含退出码和输出）、改动的文件、计划、错误；每条完整放进去或整条不放；先放最后一条请求、最后一条回答和第一条请求，再从新到旧填满预算。预算默认 16k token，并扣除目标会话已用的上下文、这一轮的输入和留给后续工作的空间。开头写明省略了多少条，以及怎么用内置的 `thread_read` 工具读省略的部分。
- **交接记录**：每份交接是 `thread_handoffs` 里的一行，记着来由、覆盖范围、选了哪些条目、发出去没有；会话历史另外投影成 `thread_items`，挑选、分页和增量判断都读它，事件日志仍然是源头。

## Considered Options

- **切换时让旧 Agent 或另一个模型写总结**：总结能带上原文里看不到的推理，但每次切换要多跑一轮、多花钱、多等十几秒，内容也说不准；按规则挑原文是确定的，缺的部分 agent 能用 `thread_read` 自己读。t3code 也没有做模型总结。以后如果挑出来的原文不够用，再单独考虑。
- **每次切换都开新原生会话，只靠交接**：实现最简单，但原生会话里的推理、读过的文件、工具状态全丢，来回切换时每次都要重新交接整个会话。
- **伪造 Claude 的会话 JSONL 或 Codex 的 rollout 文件，把历史塞成原生历史**：保真度最高，但两个格式都不是公开接口，CLI 一升级就可能坏。Codex 有公开的 `thread/inject_items`，交接通过它作为历史消息注入；不支持时才拼在用户消息前。

## Consequences

- 一个会话里同一个实例最多一个活跃原生会话，但可以有多个停放的；切换不再把它们标成停止，只有确认原生会话不存在时才停止。
- 一份切换交接还没发出去就又切换了，它会被作废：它是交给前一个实例的。
- 用户消息以 Agent 命令开头（`/compact`、`$skill`）时，这一轮不带交接，留到下一轮，否则 CLI 认不出命令。
- `thread_read` 只读，Host 直接放行它的审批请求；否则交接让 agent 去读历史，它会停在审批上等人点。
- 跨实例 fork 时如果两个实例接的是不同的 API 提供方，历史里的 thinking 签名可能通不过校验；这种失败目前不会自动退回交接。
