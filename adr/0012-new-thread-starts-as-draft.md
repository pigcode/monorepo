# 新会话先是草稿，第一次发送才建会话

参照 ZCode 的新建任务：侧栏的「新会话」、项目行的加号、⌘N、命令面板与「创建插件」都只进入新会话草稿，不调用 `thread.create`，侧栏里也不出现一行。草稿页上方选项目（默认是当前会话或最近用过的项目），输入框里选 agent、模型和权限，这些选择在本次运行里一直沿用。第一次发送时才建会话：`thread.create` 带上选好的 `modelId` 与 `permissionMode`，打开 tab，再开始 run；侧栏的新行和会话内容在同一次更新里出现。右侧面板和底部终端挂在会话上，在草稿里打开它们也会先建会话。应用启动、归档最后一个会话后看到的也是草稿页。

## Considered Options

- 保持点「新会话」就建会话：每点一次侧栏就多一个没用的「新会话」，用户要自己归档。
- 草稿里选了模型后用 `thread.switchAgent` 设模型：会在新会话开头留下一条「换成某某 agent」的标记，所以改为 `thread.create` 直接接受模型和权限。
- 草稿里也能打开右侧面板、终端而不建会话：面板、终端、文件和 Diff 都按会话 id 组织，改成按项目组织牵动太大；ZCode 也规定「必须依附会话的命令才创建会话」。

## Consequences

- 草稿的文字记在输入框的记忆里，键是固定的 `new-thread`：离开再回来、换项目都还在，发送后清空；建会话失败时文字放回输入框。
- 还没有会话时，输入框的 `@` 引用用新的 `project.files` 列出项目根目录的文件。
- 只在 Renderer 里改变入口，Host 的会话、run 与自动命名（默认标题的会话在第一条消息后取首句做标题）照旧。
