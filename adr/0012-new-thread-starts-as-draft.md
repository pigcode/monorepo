# 新会话先是草稿，第一次发送才建会话

参照 ZCode 的新建任务：侧栏的「新会话」、项目行的加号、⌘N、命令面板与「创建插件」都只进入新会话草稿，不调用 `thread.create`，侧栏里也不出现一行。草稿页上方选项目（默认是当前会话或最近用过的项目），输入框里选 agent、模型和权限，这些选择在本次运行里一直沿用。第一次发送时才建会话：`thread.create` 带上选好的 `modelId` 与 `permissionMode`，打开 tab，再开始 run；侧栏的新行和会话内容在同一次更新里出现。右侧面板和底部终端都不建会话（2026-11-11 修订，见下）：草稿里打开时挂在草稿的项目上，看的是项目根目录；第一次发送建好会话后，它们原样交给这个会话。应用启动、归档最后一个会话后看到的也是草稿页。

## Considered Options

- 保持点「新会话」就建会话：每点一次侧栏就多一个没用的「新会话」，用户要自己归档。
- 草稿里选了模型后用 `thread.switchAgent` 设模型：会在新会话开头留下一条「换成某某 agent」的标记，所以改为 `thread.create` 直接接受模型和权限。
- 草稿里打开右侧面板、底部终端时先建会话（最初的做法，当时认为面板、文件和 Diff 都按会话 id 组织，改成按项目牵动太大）：用户只是想看看文件、跑条命令，侧栏却多出一个空的「新会话」。2026-11-11 对照 ZCode 改掉：ZCode 的右栏状态按任务存，没有任务时用 `__draft__` 这一份；浏览器、文件、代码查看、终端在草稿里就能开，git 标签整个工作区共用，只有子代理、后台命令输出、计划详情、工作流这类本身属于任务的标签要有任务。
- 草稿换项目时把草稿的面板一起搬过去：面板里的文件、终端都是旧项目的，搬过去只会混淆，所以每个「草稿 + 项目」各有一份。

## Consequences

- 草稿的文字记在输入框的记忆里，键是固定的 `new-thread`：离开再回来、换项目都还在，发送后清空；建会话失败时文字放回输入框。
- 还没有会话时，输入框的 `@` 引用用新的 `project.files` 列出项目根目录的文件。
- 只在 Renderer 里改变入口，Host 的会话、run 与自动命名（默认标题的会话在第一条消息后取首句做标题）照旧。
- 右栏与终端用到的 Host 命令（`workspace.*`、`git.status`、`git.diff`、`pr.status`、`pr.create`、`terminal.open`）接受 `threadId` 或 `projectId`，只能给一个；`projectId` 看项目根目录。
- 各标签在草稿里的样子：浏览器、终端、文件树和文件、Diff（项目根目录相对 HEAD 的未提交改动）、PR（项目当前分支）、插件的 Surface 照常可用；worktree 属于会话，草稿里不显示选择器；检查点属于会话的 run，草稿里置灰，提示发出第一条消息后才有。草稿里开的浏览器还不交给 agent 控制，建好会话后才交给那个会话的 agent。
- 界面里右栏标签、未保存的文件修改按「面板 key」保存：会话里是会话 id，草稿里是「第几个草稿 + 项目」。草稿建成会话时新会话沿用这个 key，面板不重新挂载，开着的终端、浏览器、改了一半的文件都留下。
- 右栏和底部终端开没开，每个草稿各记一份，新草稿默认收起；会话之间仍共用一份，草稿建成会话时会话接过草稿的开关。
- 草稿里开的终端在 Host 上属于项目、不属于会话：交给新会话后，归档会话时由界面卸载面板关掉它；移除项目时 Host 关掉这个项目的全部终端。离开草稿（切到会话、换项目）时草稿里的终端关掉，和切换会话时一样；右栏标签记着，回到这个草稿时还在。
